AI, Gen AI and Agentic AI, told plainly

Three terms people mix up in meetings. This guide separates them, shows where each one fits in a normal workday, and ends with a 30-day plan you can start this week.

AI predictsFinds patterns, scores and recommends.
Gen AI createsWrites text, code, images and summaries.
Agentic AI actsPlans steps, uses tools, works toward a goal.

What AI is, and how the three terms relate

Artificial intelligence is software that does tasks that normally need human judgment: spotting patterns, understanding language, making predictions. Generative AI is one capability inside it. Agentic AI is a way of using that capability to pursue a goal.

Artificial intelligencepredicts
Machine learninglearns from data
Generative AIcreates from a prompt
Agentic AIacts until the goal is met

The nesting is a simplification. Some agents use no generative model, and plenty of generative tools never act on their own.

Three kinds, one scenario: a suspicious payment

TypeMain jobIn the payment scenarioAutonomy
Traditional AIClassify, predict, recommendScores the payment as 92% likely to be fraudOne defined task
Generative AICreate or transform contentDrafts the note to the customer explaining the holdResponds to an instruction
Agentic AIWork toward a goal across stepsPulls the account history, checks recent disputes, drafts the note and asks an analyst to approve itChooses next steps within limits

The analogy: a smoke alarm detects. A colleague drafts. An assistant investigates, prepares the response, updates the system and checks with you before sending.

How generative AI works

A generative model learns patterns from huge collections of examples. When you give it an instruction, called a prompt, it produces a likely response one small piece at a time. It does not automatically check whether each sentence is true.

  1. TrainLearn patterns from examples
  2. PromptYou give instruction and context
  3. GeneratePredicts the next piece, repeatedly
  4. ReviewYou check and decide

Words you will hear

  • LLM: a model trained on large amounts of text to understand and write language.
  • Token: a small chunk of text, sometimes a word, sometimes part of one.
  • Context window: how much the model can consider in one conversation.
  • Multimodal: works with text, images, audio or video.
  • Hallucination: a confident answer that is false or invented.

A better prompt: Role, Task, Context, Format, Limits

Role: You are a project manager.
Task: Summarise the update below for senior leaders.
Context: The launch moved two weeks because of a vendor delay.
Format: Five bullets: progress, risks, decisions needed, next steps, owner.
Limits: Do not invent information that is not in the update.

Making AI know your material: RAG and fine-tuning

A general model does not know your latest policies or project data. Retrieval-augmented generation (RAG) searches your documents first, then hands the relevant passages to the model. It is like asking a colleague to look up the policy before answering.

  1. Your question
  2. Find relevant files
  3. Model reads the evidence
  4. Answer with sources
ApproachThink of it asUse it when
PromptingClear instructions to a colleagueYou need a better response to a task
RAGGiving them the right reference documentsThe answer must use current or private information
Fine-tuningTraining them on specialised examplesYou need consistent style or behaviour that prompting cannot reach

Rule of thumb: improve the prompt first, add RAG when the model needs your information, consider fine-tuning only with a clear reason and good examples. Related ideas: an embedding is a numeric fingerprint of meaning, vector search finds content with similar meaning, and grounding ties an answer to reliable sources.

What an agent is

An AI agent is software given a goal, instructions and a set of tools. It decides the next step, looks at the result and continues, inside limits that people set.

  1. Understand goal
  2. Plan steps
  3. Use tools
  4. Check result
  5. Deliver or ask

Example: you ask for help with a delayed milestone. The agent reads the tracker, finds overdue tasks, checks recent status notes, drafts a risk summary and prepares follow-ups. A person approves anything that leaves the building or changes an official record.

The building blocks

PartPlain meaning
ModelThe reasoning engine that interprets instructions and picks the next step
Goal and instructionsWhat success looks like, what the agent may do, when it must stop
PlanningBreaking a big task into smaller steps
ToolsSearch, email, spreadsheets, databases, APIs
MemoryThe current task's notes and useful past context
OrchestrationThe logic that coordinates steps, tools or several agents
GuardrailsPermissions, limits, approvals, logs, safety checks

The loop: think, act, observe, decide. It stops when the goal is met or a limit is reached. An assistant helps you respond to a request. An agent can take several steps toward a goal. Autonomy varies and is never unlimited by default.

Prompt, workflow or agent?

Most tasks do not need an agent. A prompt or a fixed workflow is cheaper, faster and easier to control. Answer four questions about your task.

Can you write the steps down in advance?
Does it need information or tools beyond what you can paste into a prompt?
Does the next action depend on what gets discovered along the way?
Could a wrong action cost money, lose data or damage trust?

Starting answers are an example: a one-off summary task.

NeedBest starting point
Turn meeting notes into five action itemsPrompt: paste the notes, ask for owners and due dates
Every Friday, build the same status report from a fixed trackerWorkflow: same steps, same order, every week
Find out why a release slipped across several systems and propose a recovery planAgent: the path depends on what the evidence shows

Common agent patterns

  • Prompt chain: one AI step feeds the next in a fixed order.
  • Routing: classify the request, send it to the right specialist.
  • Single agent: one agent picks tools and steps until done.
  • Orchestrator and workers: a lead agent splits work among specialists and merges results.
  • Multi-agent team: agents collaborate or review each other. Use it only when the extra coordination earns its cost.

AI at work

Generative AI produces or transforms one piece of work. An agent coordinates several steps toward a finished outcome.

Case: quarterly portfolio data

An AI-enabled workflow can explain a valuation movement or draft commentary on a data-quality exception. A more agentic system can fetch the relevant files, compare records across sources, find inconsistencies and route an exception report to the right reviewer.

The boundary stays clear: the system does not silently overwrite historical valuations, change official books and records or publish client-facing figures. Those actions need authorised controls, reconciliation and human sign-off.

What makes a good use case

  • A repetitive task that eats real time.
  • A clear definition of a good result.
  • Access to reliable data and approved tools.
  • A way to measure time saved, quality gained or errors avoided.
  • A safe route for exceptions and human decisions.

Building your first agent

Pick one narrow, low-risk task. Build the simplest version that completes it. Add complexity only when testing shows you need it.

DayWhat to do
1Choose the task. Write what "done" means. Collect about 20 real examples.
2Do the task by hand. Record the steps, tools and decisions.
3Build a simple version: one prompt, one or two read-only tools.
4Test on your examples. Log mistakes, improve instructions.
5Add one write action only if needed. Put human approval in front of it and set limits.
6Run in shadow mode: the agent proposes, a person decides.
7Review results, failures and logs. Decide whether it is safe and useful enough to expand.

Design tools like a briefing for a new colleague

  • Use clear names, such as search_orders or create_draft.
  • Say when a tool should and should not be used.
  • Keep inputs simple and results short and useful.
  • Start read-only. Allow changes to records only when justified.
  • Give each agent only the access it needs.

MCP and memory

The Model Context Protocol (MCP) is an open standard for connecting AI applications to external tools and data, like a shared plug. It does not make a system safe or grant permissions by itself. Access still has to be configured and controlled.

Memory comes in three kinds: working memory (the goal, recent steps and tool results), short-term notes (a running plan for a long task) and long-term memory (past cases, preferences or company knowledge, retrieved when needed).

Risks, guardrails and measuring results

The more freedom a system has to act, the more you need to control its access, check its work and keep a person accountable.

RiskWhat can go wrongProtection
HallucinationA confident but wrong answerUse trusted sources, ask for evidence, verify important facts
BiasOutputs unfairly favour or disadvantage groupsTest varied cases, keep human review on important decisions
PrivacySensitive data goes to an unapproved toolUse approved tools, minimise personal data, follow policy
Prompt injectionText in a file or web page tries to steer the agentTreat external content as data, not instructions; restrict permissions
Over-autonomyAn agent sends, deletes, pays or changes something wronglyRequire approval for high-impact or irreversible actions
Over-reliancePeople stop checking and errors go unnoticedSpot-check results, keep a named human owner

How you know an agent is working

  • Task success rate: how often it finishes correctly.
  • Time to complete: faster than the current process?
  • Cost per run: do benefits outweigh model and tool costs?
  • Human intervention: how often someone must correct or take over.
  • Safety and quality: right tools, right order, no unsafe actions.

Before launch

Your 30-day roadmap

You do not need to become a developer. The aim is to understand the concepts, use AI responsibly and build confidence through small daily exercises. Use only non-confidential material and follow your organisation's AI policy throughout.

Week 1

AI and Gen AI basics

Get comfortable using an assistant and learn to doubt it.

DaysDo this (about 30 to 45 minutes a day)
1Read sections 1 and 2 of this guide. Explain AI, Gen AI and agents to a colleague in two minutes.
2Ask an assistant to summarise a public article. Then read the article and mark anything it got wrong.
3Ask it to explain one concept you find confusing, first for a beginner, then for an expert. Compare.
4Draft a professional email with it. Edit the tone until it sounds like you.
5Deliberately try to catch a hallucination: ask about a niche fact and check it against a trusted source.
6Write down three tasks from your own week where Gen AI could help and three where it should not be used.
7Review. Keep a short list of what worked and what needed fixing.

By the end of the week: you can explain the three terms, you have a feel for where the tool is reliable, and you have a habit of checking facts.

Week 2

Prompting and your data

Learn to get consistent results and to ground answers in real material.

DaysDo this (about 30 to 45 minutes a day)
8Rewrite one weak prompt using role, task, context, format and limits. Compare the two outputs.
9Give the same task to the assistant with and without an example of the output you want.
10Ask for a table, then a bulleted summary, then a one-line answer from the same material.
11Use only non-confidential documents. Paste one in and ask three questions that need its details.
12Ask the assistant to quote the passage that supports each answer. Check the quotes.
13Save your three best prompts as reusable templates with blanks to fill in.
14Review. Note what you changed in prompts that made the biggest difference.

By the end of the week: you own a small set of tested prompt templates and know when an answer needs a source.

Week 3

Workflows and tools

Move from one-off prompts to a repeatable process.

DaysDo this (about 30 to 45 minutes a day)
15Pick one repeatable task. Write its inputs, steps, checks and output on one page.
16Mark each step: always the same, needs judgment, or needs outside information.
17Turn the fixed steps into a chain of prompts, where one output feeds the next.
18Run the chain on five real examples. Record time taken and mistakes.
19Add one automated check, such as a format check or a required-fields check.
20Try one low-risk automation with an approved tool, such as a draft that waits for your review.
21Review. Calculate time saved per run and decide if the workflow is worth keeping.

By the end of the week: you have a working workflow with a measured result and a clear view of where human review sits.

Week 4

Agents and responsible use

Design a safe, narrow agent on paper and make the case for it.

DaysDo this (about 30 to 45 minutes a day)
22Use the decision tool in this guide on three tasks. Write down why each is a prompt, workflow or agent.
23Choose one narrow agent use case. Write the goal, what "done" means and when it must stop.
24List its tools. Mark each read-only or write, and remove any it does not truly need.
25List the actions that need human approval and the limits for steps, time and spend.
26Write ten test cases, including two awkward ones and one that tries to trick it.
27Fill in the launch checklist in the risks section and name an owner.
28Walk through a shadow-mode run on paper: what would the agent have proposed, and what would you have changed?
29Write a one-page proposal: problem, design, risks, success measures.
30Present it to a colleague or manager and collect their questions.

By the end of the week: you have a one-page agent proposal that a reviewer could approve, change or reject.

Month-end self-check

  • I can explain AI, Gen AI and agentic AI to a non-technical colleague.
  • I have prompt templates I trust and I verify important facts.
  • I have mapped at least one real task as a workflow and measured the result.
  • I can say when a task does not need an agent.
  • I know the guardrails any agent would need before it touches real work.

The takeaway

Start with the problem, not the technology. Use a prompt for a simple task and a workflow when the steps are known. Consider an agent when the path depends on what it discovers, and keep people in control of important decisions.
